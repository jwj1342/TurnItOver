# 从照片／视频到可验证三维程序：候选 pipeline

核查日期：2026-09-11。依据上游官方仓库和项目说明；尚未安装或复现下列 pipeline。
“接入成本”和优先级是针对本仓库接口的工程判断，不是实测性能比较。

## 当前定位

现有 toy cabinet 用于检验渲染、关节、腐蚀和检查器。它不是照片重建结果，也不足以支撑重建质量或真实泛化结论。
改进展示的下一步应是引入真实输入和真实生成程序，同时保留 toy 作为快速回归测试。

RP 当前锁定单个可动物体，并排除视频输入和场景级任务。若改为视频场景重建，需要同步修改研究对象、
动作空间、真值与评测协议。多视角重建的相机运动与物体关节运动也必须区分。

## 候选与适配

| Pipeline | 输入与产出 | 对本研究的作用 | 主要缺口 |
|---|---|---|---|
| [img2threejs](https://github.com/img2threejs/img2threejs) | 参考物体图 → 程序化 Three.js 工厂、层级结构 | 最接近现有代码生成／浏览器路线；可研究分阶段生成与视觉反馈 | 上游是依赖宿主 agent 能力的工作流，不能假设为一个普通 REST 服务；须适配 `{root,joints,dispose}`、部件命名、关节绝对控制 |
| [Articulate-Anything](https://github.com/vlongle/articulate-anything) | 图像／视频／文本 → 资产检索、部件布局、关节建模；有 actor–critic 迭代 | 优先考察真实可动物体和反馈循环 | 依赖 PartNet-Mobility 与仿真栈；视频路径还需运动跟踪；检索来的几何不是原照片的精确几何真值；到 Three.js 需资产／关节适配 |
| [Real2Code](https://github.com/MandiZhao/real2code) | 视觉观测 → 分割、形状补全、关节代码；真实数据使用 DUSt3R 多视角结果 | RP 中的关节重建质量基线及数据参考 | SAM 微调、形状补全、CodeLlama 等多个模块和权重；上游 Python 3.9 环境；不是现成 Three.js 工厂 |
| [TRELLIS.2](https://github.com/microsoft/TRELLIS.2) | 图像 → 高细节三维资产与 PBR 材质 | 几何／外观资产候选，可摆脱纯 box 展示 | 不直接给出我们要求的语义关节程序；需 mesh 导入、部件分割／标识、关节建模；官方要求至少 24 GB NVIDIA 显存及 CUDA 扩展 |
| [VGGT](https://github.com/facebookresearch/vggt) | 单张或多张场景图 → 相机、深度、点图与点轨迹 | 若扩展至场景／视频帧重建，可作为几何前端 | 输出不是可编辑关节程序；仍需网格化、语义分解、动作模型；不应与单图可动物体生成直接混成同一基线 |

Articulate-Anything 的阶段划分另见[官方项目](https://articulate-anything.github.io/)。
Real2Code 的形状与关节表示另见[官方项目](https://real2code.github.io/)。
使用前固定上游 commit，并分别核实代码、权重、检索资产、参考图片许可；它们不能互相替代。
本次仓库浏览未在 Real2Code / Articulate-Anything 根目录看到明确 LICENSE 文件，应继续确认授权，不能默认 MIT。
img2threejs 当前组织仓库列出 Apache-2.0，应以实际采用的仓库版本为准。

## 建议的两条路径

第一条用于快速形成可检验实验：真实物体照片 → 冻结 VLM 生成 TypeScript → ABI 适配 → 现有浏览器 →
固定／主动观测 → 诊断与修复。先用少量不同结构的物体跑单次生成，再接 img2threejs 的分阶段工作流或自修正基线。
本次新增的 `reconstruct` 只是这条路线的单次调用基线，并不等同于上游 pipeline。

第二条用于扩大资产和运动复杂度：考察 Articulate-Anything 的检索资产、关节结果和迭代记录，
建立包含外部 mesh 引用、坐标系、单位、部件对应关系、关节定义的导入协议。
真实 mesh 支持应独立于现有 box-only `AssetSpec` 演进；不要把细节网格压回包围盒后再宣称复现原方法。

## 接入验收，而非只看好看的截图

每个候选先跑一个参考图／视频小样本，保存输入、上游版本、模型与提示、原始输出、转化后的程序、渲染图和运动视频。
核验部件数量与标识、坐标系、关节方向与限位、资源释放，以及哪些检查器在没有参考真值时仍适用。
再做多对象试验，报告重建／编译／ABI 失败，不只展示成功案例。

“看起来像”与“关节正确”需要分别评测。只有单张真实照片时，隐藏结构、尺度和关节轴没有完备真值，
不能直接沿用合成腐蚀的完美标注口径。若引入视频真值，也要区分给生成器的输入和留作评测的证据。

## 与当前仓库的边界

- 已有：合成数据闭环、浏览器观测、截图／视频导出。
- 本次新增：独立多服务商模型调用、按角色配置、单次照片到程序入口与离线准备模式。
- 未有：任何上述上游的完整复现、真实资产转换器、视频理解路径、主动 VLM 策略、多轮修复、正式真实数据评测。
