# 修复实验执行层与真实模型试验

`turnitover/repair` 提供可审计的代码修复循环：当前程序与公开反馈进入冻结生成器，
返回事务式精确文本编辑；浏览器执行新程序，独立检查器记录得分，继续下一轮。
编辑可以覆盖程序任意位置，不限制为已知腐蚀参数。

随仓库提供[测量快照](../results/2026-09-12/README.md)，可离线核对下述结果。
完整资产到试验的准备顺序见[接手指南](research-status.md)。

## 已实现的执行约束

- 每个 old 字符串必须在当前源码中恰好匹配一次；多项编辑以原始文本为基准同时应用，禁止重叠。
- 编译失败或移除必需关节的提案计一次失败尝试，保留上一个可执行程序。
- 可执行但质量下降的程序仍会进入下一轮，不使用真值偷偷回滚到最佳状态。
- 记录全部请求、图片、响应、程序版本、审计结果、模型 token 和观察成本。
- 停止由生成器决定；通过确定性检查不会隐式终止基线。
- 汇总首次达标轮次、最终达标、无改善率、精确源码重访率、停止轮次误差及单位 token 增益。
  精确源码重访不是 RP 的几何 epsilon 振荡率，二者不能混报。
- 内部审计异常使实验标记 incomplete，不伪装成普通无效模型编辑。

审计覆盖正确参考中的静止状态及所有关节下限/中点/上限，并检查运行时预算。
这避免负下限、零上限关节只检查 limit 而漏掉运动学错误。
所有判断仍仅限配置中的几何与运行时约束。

## 准备好的四条件工程试验

目录：`output/repair-pilot-prepared-v2/`。干净、偏移、轴错误、组合错误各一个门样本，
共四种反馈条件，每条修复轨迹最多三次生成器调用，最大调用数 48。

| 条件 | 候选观察 | 是否提供确定性约束失败反馈 |
| --- | --- | --- |
| fixed | 固定顺序 | 否 |
| gold_constraints | 同一固定顺序 | 是 |
| oracle_observations | 初始腐蚀 oracle 顺序 | 否 |
| combined | 同一 oracle 顺序 | 是 |

全部条件使用同一张静止参考图和相同观察预算。普通条件的 prompt 不含内部审计分数、
正确程序或腐蚀标签；gold 条件只增加当前失败的确定性约束。
准备目录已有可直接检查的初始源码、16 份首轮 prompt、对应图片和私有初始审计。
v2 同时冻结参考程序、案例元数据和文件哈希。执行前检查全部文件哈希；每条轨迹的
首轮 prompt 和图片还必须与准备内容逐字节一致，之后才允许调用生成器。
准备与执行共享图片命名逻辑，反馈中的 image_ref 与模型图片顺序一致。

```bash
source scripts/setup_local.sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python scripts/prepare_repair_experiment.py --out output/repair-prepared-new
# 配置好 .env 中的 generator 后执行；输出目录必须不存在
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python scripts/run_repair_experiment.py --prepared output/repair-prepared-new --out output/repair-model-run
```

冻结生成器已按用户选择配置为 OpenRouter 的 `openai/gpt-5.6-sol`，输出上限 8192 tokens，
单次请求超时 180 秒，不自动重试。凭证仅保存在被 Git 忽略的本地 `.env` 中。
首条真实调用位于 `output/repair-generator-sol-smoke-v1/`：组合错误案例在 gold_constraints
条件下返回有效补丁，独立浏览器审计分数由 0.4 升至 1.0，全部配置检查通过。
该调用使用 46,257 tokens，OpenRouter 返回费用 $0.1313835。它是流程 smoke，单独计费、
不纳入四条件比较。四条件正式 pilot 已完成，输出到 `output/repair-sol-pilot-v1/`；
`summary.json` 保存执行汇总，`analysis.json` 区分损坏/干净案例并核对实际费用。
不应把使用知道正确答案的测试桩完成修复记为模型结果。

批量入口已用明确标记为 `scripted-stop-fixture` 的测试桩完成 16 条路径验证，
结果在 `output/repair-runner-fixture-v2/summary.json`；四个条件均只有原本干净的案例通过。
全部首轮输入通过字节一致性检查。另已验证缺失模型配置时会在创建结果目录和 API 调用前退出。

当前准备版的观察序列基于初始腐蚀，不会在代码修复后重新求解；约束反馈也不等于完美语义诊断。
门测试族只有一个关节，固定扫描已能暴露全部本轮测试缺陷，难以区分主动选择优势。
因此这四条件试验首先验收执行与成本记录，不能替代 RP 的完整三种 oracle 上界：
后者仍需逐轮更新观察/诊断 oracle，并纳入有代表性的多关节案例。

## 本轮解释边界

本轮固定的是模型标识与请求配置；未指定供应商权重快照、temperature 或 seed，不能声称逐次调用可复现。
每个条件只有三个损坏案例和一个干净对照，分别报告修复成功与干净保持，避免把原本通过算作修复。
条件按固定顺序执行且只有一次采样；缓存和路由可能影响实际费用，不能把费用差异直接归因于反馈策略。
费用使用响应 `usage.cost` 汇总，token 使用供应商总量（含其计入总量的推理 token），
不以公开标价推算替代账单返回值。首条独立 smoke 不并入条件统计。

## GPT-5.6 Sol 实测结果

2026-09-12 完成全部 16 条轨迹，实际 30 次调用（上限 48），1,342,725 tokens。
所有响应均返回可解析且可执行的编辑或停止，没有无效补丁或不可执行提案。
以下成功只指配置中的几何与运行时检查全部通过。

| 条件 | 损坏案例修复 | 干净保持 | API 调用数（含停止） | 返回费用 USD |
| --- | --- | --- | --- | --- |
| fixed | 1/3 | 1/1 | 7 | 0.8291120 |
| gold_constraints | 3/3 | 1/1 | 8 | 0.8374565 |
| oracle_observations | 3/3 | 1/1 | 7 | 0.8224845 |
| combined | 3/3 | 1/1 | 8 | 0.9552930 |

批量费用合计 $3.4443460；加上独立 smoke $0.1313835，总计 $3.5757295。
所有 30 次批量响应均包含 usage.cost，没有缺失费用记录。各条件实际获取观察数为
42、48、42、48；每轮预算相同，总数因停止时机而不同。

| 案例 | fixed 首次通过轮次 | gold_constraints | oracle_observations | combined |
| --- | --- | --- | --- | --- |
| 组合错误 | 未通过，修改一次后停止 | 1 | 1 | 3 |
| 轴错误 | 未通过，修改一次后停止 | 2 | 1 | 1 |
| 偏移错误 | 1 | 1 | 1 | 1 |
| 干净对照 | 0 | 0 | 0 | 0 |

该结果表明，在这些案例上 Sol 能执行有效修复，反馈条件值得继续研究；不能据此断言
观察策略优于诊断，或达到 RP 的 20% 效率改进路线判断。fixed 在两例未通过时提前停止，
调用少不代表效率高；combined 在组合错误上反而用了更多轮。没有重复采样、只有一个门
资产族，而且固定扫描在该族本已暴露所有测试缺陷；oracle 顺序优势可能来自顺序、
状态分配或随机生成，不能归因于“主动策略找到了固定策略无法获得的证据”。

下一项有辨别力的实验需要多个关节和多个留出资产族，并在每轮修改后重算可用证据与
诊断 oracle，再做重复采样。在此之前，不宜直接扩大微调投入。
