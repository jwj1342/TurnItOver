# API Pipeline 实验报告

日期：2026-10-20–21。分支 `laq/api-pipeline`，起点为 `laq/sft-dataset` 的 `99db3a7`。运行入口、配对协议、原始记录和独立评分均已完成；没有训练、扩充数据集、改动冻结 Test 或更换 API 模型。

## 完成范围与协议

已真实执行一次共享 API 生成、Chromium 渲染、主动/固定观察、结构化诊断、Generator 精确补丁修复，以及修复后的全新浏览器验证。复用原生 generation、ObservationSession、动作执行器、Verifier schema 和 iterative repair；新增薄编排、严格 K、API 台账、独立动作重放评分及限定恢复接口。通用 `single` 入口支持自己的公开任务与参考图；本次配对评分入口固定用于下面的受控案例。[运行说明](api-pipeline.md)、[预检代码审查](api-pipeline-code-review.md)。

公开输入是一套自编三部件、双关节物体的尺寸/位置/运动规范和新渲染的参考图，参考实现独立于 API 输出。共享初始程序确实来自 k3-256k（程序 SHA `acde36209a8c6b03`），独立检查通过32/32项；在该程序上预先定义 clean、drawer 位置偏移、door 轴错误三例。独立重放确认偏移只影响 drawer、轴错误只影响 door 的运动状态，初始分别通过32/32、22/32、28/32项。私有参考源码、注入标签和评分不进入模型输入；公开设计规范属于任务输入。

所有角色使用本地同一 teacher 配置的 k3-256k、temperature=1，返回模型 ID 均一致。共享生成上限4096；比较阶段所有决策、诊断与修复统一8192。每轮两组均 K=4、最多一次视觉修复、一次 runtime repair；初始源码、参考图及真实初始截图逐字节一致，使用同一冻结 Chromium harness。Active 额外的动作决策 API 调用全部计费。固定顺序为 stats、front、oblique_fr、drawer limit，因此 K=4 时未检查第二关节。

最小门轴案例 `api-minimal-v6` 是**明确标记的分段恢复**：原 `v5` 已完成诊断、真实补丁和重新观察，但最后诊断遭524；新目录仅以相同提示与原图续接一次最终诊断，然后首次运行 Fixed。原失败历史保留，成本合并，没有新增 Active 观察或修复。随后 `api-paired-v6` 完整执行 clean 与偏移两例，全程使用 SSE。这两个阶段不能合称一次连续实验。

以下为初次诊断及修复结束后的独立评分。质量仅覆盖 contract、有限采样几何/关节状态和 runtime 预算；不代表材质、碰撞或完整物理正确性。

| c00 clean | Active | pass，正确 | 32/32，通过 | 0 / 0 | 4 | 5 / 16,983 |
| c00 clean | Fixed | fail，误报 drawer 轴 | 32/32，通过 | 1 / 0（Generator stop） | 4 | 2 / 11,326 |

c02 Active 第4个动作检查门运动，诊断引用 step 3；Generator 将实际候选的 X 轴旋转改为 Y 轴，第一修复轮独立通过，重新观察后模型判 pass。Fixed 没有检查该门，误判 pass。c00 Fixed 的误报反馈也确实送入同一 Generator，返回 `stop`，未改坏正确程序；该组最终状态为 `max_visual_revisions`，没有获得 Verifier pass。c01 两组均漏检；Active 已选择 top 视图和两个关节动作，仍未发现位置偏移。不能以观察覆盖或 schema 合法替代缺陷识别。

三个案例初次检测/类型集合精确匹配：Active 2/3，Fixed 0/3；最终独立程序通过：Active 2/3，Fixed 1/3。部件定位累计 TP/FP/FN：Active 1/0/1，Fixed 0/1/2。唯一正确阳性 c02 Active 的类型、部件、关节均匹配，引用1个存在的步骤且几何见证一致1/1；c00 Fixed 的2个引用均存在，但见证一致0/1 finding。无 findings 的空引用不记作“证据正确”。见证指标只是独立几何不一致的必要代理，**未完成人工自然语言解释/图像可见性审查**。

配对阶段 Active 共22请求、75,619已知tokens、16观察；Fixed 4请求、19,077tokens、12观察。每轮观察预算相同，Active 因修复多了一轮；不是等 token 成本比较。动作耗时和逐轮明细见机读结果。

## 成本与故障处理

[完整总账与逐组结果](../results/2026-10-21-api-pipeline/summary.json) 纳入全部9个原始台账各一次：**44次尝试，39次完成、5次失败，145,467已报告tokens，4次usage未知；货币费用全部未知**。共享生成1次/3,673tokens；配对与修复26次/94,696已知tokens；其余排错及失败17次/47,098已知tokens。c02 的失败524已经计入其12次 Active 请求，不再重复收费。请求数上限不是供应商货币硬上限。

实际修正的兼容问题：k3-256k 只接受 temperature=1（两次400确认）；已有 harness 把命名 Mesh 当部件导致几何假阴性（改为与 ABI 一致的 Group 部件识别，候选源码未变）；4096输出上限的一次最终诊断全部用于推理、无JSON（随后两组统一8192）；一次120秒客户端超时和一次约126秒524（300秒客户端等待仍不足以解决代理超时，增加严格 SSE 记录与限定恢复）。所有旧请求及失败目录保留；旧 harness 的调试结果不进入上述效果统计，没有为追求成绩调换模型或重采样初始程序。

## 验证、复现与限制

最终相关单测104项通过；真实 Chromium 测试12项通过，覆盖真实动作、部件句柄、双组脚本 API fixture 闭环及恢复（fixture 不计实验结果）。恢复成本补充断言另通过1项。Web build/typecheck 通过。较早全量 unit 为311通过、4失败、2跳过；4项失败均为历史 v2/v3 数据清单的旧脚本哈希，涉事脚本与分支起点字节一致，未改写历史数据清除失败。

[运行包及离线复现说明](../results/2026-10-21-api-pipeline/README.md) 保存真实请求/响应、SSE原始字节、程序各版本、PNG、动作历史、诊断、补丁、失败记录、台账、runtime 及环境/文件哈希。API配置冻结仅能核对本地配置与返回ID，不能证明网关权重快照或保证随机采样逐次一致。

当前完成的是一套物体、两个受控缺陷、每组一次采样的真实可审计闭环。c02 的差异同时受 Fixed K=4 未覆盖第二关节影响；其分段恢复、跨阶段缓存/时间差异和未知调用费用也限制比较。公开精确设计规范帮助 Generator 修复，不等于仅凭照片生成；几何检查不覆盖材质、组合关节全状态或物理。结果支持这次闭环跑通及个例差异，**不足以证明 Active 普遍优于 Fixed**。
