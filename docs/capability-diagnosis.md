# 小型 benchmark 能力诊断（2026-09-12）

本轮已完成自动证据标注、训练格式导出和冻结 Qwen3-VL-2B-Instruct 的分层诊断。
结果支持把观测获取、图像差异辨别、缺陷分类和输出协议分开验证。
它没有证明大规模微调有效，也没有验证对生成器迭代效率的改善。

## 范围与数据

原始 benchmark 为六个 ReplicaCAD 资产族、96 个腐蚀/干净样本。
训练/验证/测试为 64/16/16；测试的 16 个样本来自同一个门资产族，不是 16 个独立对象。
测试共有 12 项关节轴错误和 11 项部件偏移。
本轮在观察测试输出后追加了协议和简化任务诊断，因此这些数字是开发诊断，
不能作为提示词选择之后的最终盲测成绩。正式结论仍需新的资产留出集。

## 观测获取

Qwen 的 16 个在线 episode 都主动结束并返回 uncertain，没有格式错误。
其 12 项关节轴错误均未取得像素差分证据。原始 JSON 与模型调用记录在
`output/qwen-active-benchmark-v1/`，Slurm 21783649 已成功完成。

全 96 样本的 oracle/固定/随机六步暴露数为 115/76/66（分母 120）。
这与测试集上 oracle 和固定都达到 23/23 并不矛盾：门只有一个关节，固定探查已足够。
因此现有测试拆分不足以证明复杂多关节任务上的自适应观测优势。

## 视觉辨别与分类

为了隔离复杂 JSON 协议影响，额外使用简短、无诊断示例的任务。
最明显图像对从已获得的 oracle 轨迹中按像素差分选出，属于特权证据条件。

| 二图差异辨别 | 正例召回 | 全样本答对 | 格式错误 |
| --- | ---: | ---: | ---: |
| 静止正视图对 | 2/11 | 7/16 | 0 |
| 最明显已获取图对 | 12/14 | 14/16 | 0 |
| 候选图与自身比较 | 无正例 | 16/16 | 0 |

结果在 `output/qwen-pair-readout-v1/`，Slurm 21783780。
标签是像素阈值代理，不是人工感知标注；自身比较是较容易的负例。

进一步只要求返回缺陷 ID，提供静止和最明显已获取状态：

| 参考条件 | 部件偏移 TP/FP/FN | 关节轴 TP/FP/FN | 格式错误 |
| --- | --- | --- | ---: |
| 单张静态参考 + 候选观察 | 9 / 2 / 2 | 3 / 0 / 9 | 0/16 |
| 两个状态的成对参考 | 11 / 5 / 0 | 0 / 0 / 12 | 0/16 |

结果在 `output/qwen-defect-readout-v1/`，Slurm 21783956。
成对条件将全部 16 个样本都预测为部件偏移，不能把偏移召回为 1 解释为有效分类。
看到差异、理解差异为何发生，以及判断是结构还是运动学错误，是不同的能力。

## 完整诊断协议

每个条件都是同一测试集的 16 个样本；错误输出计漏检，不删除。

| 获取轨迹/参考条件 | 原动作与判定协议无效数 | 仅最终判定协议无效数 |
| --- | ---: | ---: |
| Oracle / 单参考 | 7 | 16 |
| Oracle / 成对参考 | 9 | 16 |
| 固定 / 单参考 | 3 | 16 |
| 固定 / 成对参考 | 12 | 16 |
| 随机 / 单参考 | 1 | 16 |
| 随机 / 成对参考 | 5 | 16 |

两轮都没有合法的正确缺陷检出。原协议中合法输出为 pass 或 uncertain；
无效输出包括把动作字段写入 verdict、同时返回 pass 和 findings、复制运行时预算示例等。
改用仓库的 final_prompt 并没有改善：96 次均未满足完整协议。
原始输出保存在 `output/qwen-evidence-v1/`（21783429）和
`output/qwen-evidence-final-v1/`（21783781）。
这些现象与最小分类任务的非零检出共同说明，不能用完整协议的零检出率
推断模型没有视觉能力；也不能用简化任务结果声称完整 verifier 已经可用。

## 训练数据与工程验证

- 原始动作 BC：576 条；成对诊断：288 条，两种输入条件明确分开。
- 相同可见输入的歧义动作已聚合为经验分布，413 条带权目标、403 个输入组。
  组内变体一起打包，使用 assistant-only 加权损失。分组不会跨 split。
- 原始动作输入的 1/6 张图像、成对诊断的 12 张图像均通过本地 Qwen 处理器
  和答案 token 掩码检查。带权损失另有实际 torch 梯度验证。
- 当前仍没有单参考条件的最终诊断/停止监督，没有训练完成的模型检查点。

详见 [Oracle 与训练导出](oracle-supervision.md)。RP 关于“真值 oracle 序列可直接模仿”的
假设需补充可学习性条件；同一可见输入对应不同特权教师动作已经有实际反例。

## 后续决策

先补可见条件下的动作与停止监督，并独立验证缺陷分类，再考虑合并自然语言诊断。
尤其需要关节运动前后的分类监督、偏移与轴错误的难负例，以及不会跨资产泄漏的留出集。
新增资产应优先包含多个关节，否则无法区分主动策略与固定扫描。

RP 中“完美诊断、完美观测、联合 oracle 对生成器修复效率的三条上界”仍未执行；
当前暴露 oracle 不能替代这项实验。是否值得扩大训练投入，还需要该修复闭环证据。

后续已建立修复循环、独立浏览器验收及四条件首轮输入准备，见
[修复实验执行层](repair-experiment.md)。冻结生成器已配置为 OpenRouter GPT-5.6 Sol，首条 gold_constraints 真实修复通过全部配置检查；
四条件小规模试验已完成：固定观察修复 1/3 个损坏案例，约束反馈、oracle 观察与联合条件
均修复 3/3，四条件均保持干净对照。实际 30 次调用、费用 $3.444346（不含独立 smoke）。
这说明当前案例上生成器能够执行有效修复，但不能证明训练收益或完整 oracle 上界；
其冻结观察序列、单关节资产族和单次采样限制仍需解除。
